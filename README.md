# Системный администратор — Peaky Minds

Готовый учебный комплект к [базовому](https://stepik.org/course/301881)
и [продвинутому](https://stepik.org/course/301882) курсам. Учебный продукт —
внутренний файловый портал мастерской «Лист». Пишем команды администрирования;
программировать приложение не требуется.

## Запуск

Выделенный Linux amd64-хост, интернет для официального Debian-образа и apt.
Для basic рекомендуется 8 ГиБ RAM/25 ГиБ места; advanced — 16 ГиБ/50 ГиБ.
Каждый guest: 2 ГиБ RAM, 2 vCPU, 12 ГиБ виртуального диска. KVM ускоряет запуск;
без него используется медленный TCG. WSL может служить хостом с QEMU, но не
заменяет гостевой Debian с systemd. Альтернативные гипервизоры не проверены этим CI.

```bash
sudo apt-get update
sudo apt-get install -y git python3 qemu-system-x86 qemu-utils cloud-image-utils openssh-client
git clone https://github.com/politifan/peaky-sysadmin-lab.git ~/peaky-sysadmin
cd ~/peaky-sysadmin
git switch -c course-work course-v3.0.0
./lab up basic               # или advanced; это новый отдельный комплект
./lab status
./lab ssh node-a
```

Не запускайте изменение служб/дисков на машине хозяина. Команды следующих
Linux-уроков выполняются после входа в guest; host-команды отмечены отдельно.
`up` не заменяет уже существующий state. Не удаляйте свою `.runtime` для повтора:
там ваши диски и ключи. Для второго комплекта используйте новый каталог и
освободите loopback-порты штатным остановом прежнего.

| Guest | LAN | SSH с хоста | HTTP с хоста |
| --- | --- | --- | --- |
| node-a | 192.168.77.11/24 | 127.0.0.1:22181 | 127.0.0.1:18081 |
| node-b | 192.168.77.12/24 | 127.0.0.1:22182 | 127.0.0.1:18082 |
| dc1 | 192.168.77.13/24 | 127.0.0.1:22183 | — |

Отдельный LAN на loopback-хосте, отдельный NAT для исходящего интернета.
HTTP появляется после установки портала. При входе сравнивается fingerprint
из отдельной консоли VM, затем используются strict host keys и свой instance-id.
Образ Debian 13 закреплён датой и проверяется официальным SHA512.

## Продвинутый исходный стенд

```bash
./lab prepare             # готовый портал на двух собственных guest
./lab domain-init         # только свой dc1, перед модулем каталога
./lab http --node node-a --expected files/index.txt --out evidence/baseline-a.json
```

`prepare` сохраняет уже подготовленный документ и отказывает при чужом
существующем исходном файле. Домен — реальный Samba AD, один DC. Windows Server,
GPO, многоплощадочная HA, независимый гипервизор здесь не изображаются.
Пароль Administrator остаётся в root-only файле dc1; в задания не вставляется.

## Штатный останов и холодная копия

```bash
./lab stop node-a
./lab snapshot-vm node-a  # overlay зависит от исходных backing disks
./lab start node-a
./lab stop node-a
./lab export-vm node-a backups/node-a-full.qcow2
qemu-img info --backing-chain backups/node-a-full.qcow2
./lab restore-vm node-a backups/node-a-full.qcow2
```

Экспорт сворачивает всю цепочку в новый приватный qcow2. Restore проверяет
manifest/hash/node/instance и запускает отдельный восстановленный диск,
сохраняя прежний. Само наличие копии не подтверждает useful restore:
прочитайте прежний документ, проверьте службу, права и точку новых данных.
Копии на том же физическом носителе не защищают от его потери. Не клонируйте
одновременно DC с одной идентичностью. `./lab down` — аварийный останов своих
QEMU-процессов с сохранением дисков; для согласованного экспорта нужен `stop`.

## Как проверяется результат

Stepik проверяет текст ответа. Он не исполняет введённую команду в вашей VM.
Для command-полей проверяются изученные формы и перечисленные допустимые
варианты; произвольная эквивалентность shell не обещается. Локальный `lab http`
читает настоящий HTTP и сравнивает статус/полные байты своего документа, но
не отправляет баллы. External Grader/XQueue не подключён.

[Авторская приёмка](https://github.com/politifan/peaky-sysadmin-lab/actions):
реальные Debian VM, reboot, allow/deny ACL, nginx, плохой архив, restore,
AD/SMB, Ansible, Linux storage и Windows NTFS с действительным чтением от
другого пользователя. `qa` — авторская проверка отдельной одноразовой среды;
не повторяйте все QA-скрипты в произвольном уже заполненном guest.

Windows-модуль выполняется отдельно в выделенной Windows VM с PowerShell.
`qa/windows.ps1` создаёт своего временного пользователя и NTFS-каталог,
проверяет чтение/отказ его реальным token, затем удаляет только созданное.
CI Windows Server 2025 не подтверждает reboot Windows 11 на вашем компьютере.

Для итогового результата создайте `docs/RUNBOOK.md`: назначение узлов,
действия проверки, один отказ, причину и проверенный возврат. Не публикуйте
`.runtime`, backups, evidence с личными данными, auth, private keys и дампы.
